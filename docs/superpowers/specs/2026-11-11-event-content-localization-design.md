# Event Content Localization

Date: 2026-11-11
Status: Draft for approval

## Intent

Organizers write event titles, taglines, and descriptions in one language. The
interface can be translated, but the content stays in the source language, so an
attendee browsing the Japan edition may land on an Indonesian event page with an
Indonesian description.

This project adds opt-in multilingual event content:

- The organizer or an administrator enables it per event.
- Locales can be written manually, or drafted by AI on request and reviewed.
- The event page gains a language selector that switches the content language
  independently of the interface language.

It is a separate project from interface localization. Interface strings ship in
`docs/superpowers/specs/2026-11-11-localization-coverage-design.md`.

## Goals

- Opt-in per event, off by default, for both organizers and administrators.
- Manual per-locale editing with the source language as the fallback.
- AI drafts only when the organizer explicitly enables and requests them.
- Unreviewed drafts stay out of the public page until the organizer marks them
  reviewed.
- A per-event language selector that appears only when at least two locales are
  published.
- Correct metadata, JSON-LD, and hreflang for the selected content language.

## Non-goals

- Translating names and identifiers: venue names, city names, organizer names,
  booth company names, URLs, emails, and IDs.
- Translating numbers, dates, prices, or currency.
- Translating attendee-generated content such as meeting requests or chat.
- Translating on read. Content is translated on request and stored.
- Publishing AI drafts automatically.

## Anti-goals

- A page that silently shows machine translation as if the organizer wrote it.
- An event that gains a language selector without the organizer opting in.
- A translation that overwrites reviewed copy.
- SEO alternates that point to content that does not exist.

## Constraints

- `Event.title`, `tagline`, and `description` are single-language columns today.
- `Event.editorialBlurbI18n` is the existing per-locale JSON precedent.
- The event page is a server component with `params` only. It needs
  `searchParams` for `contentLang`.
- The OpenRouter gateway is available at `src/lib/ai/openrouter.ts` with
  `generateStructuredReport` and a Zod-schema path.
- Ownership is enforced by `resolveEventCaller` and `canWriteEvent`.
- Six locales: `en`, `id`, `ja`, `zh-CN`, `de`, `es`.

## Approaches considered

**A. Manual per-locale fields.** Accurate and fully in the organizer's voice, but
asking for six versions of every description is unrealistic, so most events
would stay in one language.

**B. Automatic translation on save.** Fast, but unreviewed machine translation of
prices, dates, or safety copy would publish directly.

**C. Hybrid with opt-in and review (chosen).** The organizer writes the source,
can edit any locale, and can request AI drafts for missing locales. Drafts carry
an origin and status. The public page shows reviewed content only. The organizer
opts in per event, and AI drafts require a second explicit opt-in.

## Design

### Data model

Add one nullable JSON column to `Event`:

```prisma
contentI18n Json? // Opt-in multilingual content. Null means off.
```

Shape, validated by a Zod schema:

```json
{
  "version": 1,
  "enabled": true,
  "sourceLocale": "en",
  "autoTranslate": true,
  "locales": {
    "id": {
      "title": "Pekan Raya Jakarta 2027",
      "tagline": "Pasar tahunan terbesar di Indonesia",
      "description": "Pekan raya tahunan dengan pameran, kuliner, dan panggung musik.",
      "origin": "AI",
      "status": "DRAFT",
      "updatedAt": "2026-11-11T10:00:00.000Z"
    }
  }
}
```

- `enabled` is the master opt-in. Disabling keeps the stored translations.
- `sourceLocale` is the language of the base columns. The organizer confirms it
  when enabling, defaulting to the current interface locale.
- `autoTranslate` is the second opt-in. When false, no AI draft can be
  generated.
- `origin` is `MANUAL` or `AI`. `status` is `DRAFT` or `REVIEWED`.
- Only locales in the six-locale set are accepted. The source locale cannot
  appear in `locales`.

### Opt-in rules

- `contentI18n` is null until an organizer or administrator enables it.
- Organizers can enable only their own events. Administrators can enable any
  event, including platform-curated listings.
- Enabling requires a source locale and at least one target locale.
- `autoTranslate` defaults to false and is a separate switch. The switch states
  that drafts are generated by an external AI provider and must be reviewed.
- Disabling hides the selector and renders the source, without deleting stored
  translations.

### Customizer and admin UI

A `Multilingual Content` card in the organizer customizer, and the same card in
the admin event console for platform-curated events:

- Master switch: `Enable translated event content`.
- Source language select.
- Target language checkboxes, with a status badge per locale: `Missing`,
  `AI draft`, `Reviewed`.
- Per-locale editor: title, tagline, and description fields, prefilled with the
  draft or the source as a reference.
- `Generate drafts` button, enabled only when `autoTranslate` is on and at least
  one target locale is missing content. It states the external provider.
- `Mark reviewed` per locale, which promotes `DRAFT` to `REVIEWED`.
- `Publish` is not a separate step. Reviewed locales are published; drafts are
  organizer-only.

### API

`PUT /api/organizer/events/[id]/content`

- Body: `{ enabled, sourceLocale, autoTranslate, locales }`.
- Validates the Zod shape, the locale set, the source locale, and field lengths
  (title 160, tagline 200, description 5000).
- Applies the ownership gate.
- Never deletes a locale unless it is explicitly removed.
- Audit action `event.content`.

`POST /api/organizer/events/[id]/content/translate`

- Body: `{ locales: string[] }`, maximum five.
- Requires `enabled` and `autoTranslate`.
- Refuses to overwrite a locale whose status is `REVIEWED`, and refuses to
  overwrite `MANUAL` content without `{ force: true }`.
- Returns per-locale results, so one failed locale does not discard the others.
- Audit action `event.content.translate`.

Translation uses `qwen/qwen3.7-plus` through `generateStructuredReport` with a
Zod schema for `{ title, tagline, description }`. The prompt instructs the model
to preserve proper nouns, numbers, dates, and prices exactly, to add no claims,
and to keep the length close to the source.

### Attendee resolution

The event page adds `searchParams` and resolves the content language in this
order:

1. `?contentLang=xx` when that locale is `REVIEWED`.
2. The interface locale when that locale is `REVIEWED`.
3. The source locale.

Only `REVIEWED` locales are public. Drafts never render on the attendee page.
The resolved title, tagline, and description override the base columns for the
hero, the themed view, metadata, JSON-LD, and the share card.

### Language selector

A `ContentLanguageSwitcher` client component, rendered only when the event is
enabled and at least two locales are `REVIEWED`:

- A labeled select with the language names, 44px minimum height.
- Selecting a language sets `?contentLang=xx` with `router.replace` and
  `scroll: false`, preserving other query parameters.
- The selected value reflects the resolved language.
- Screen readers get the label `Read this event in`.
- The source locale is always offered.

### SEO

- Canonical URL stays the base event URL without `contentLang`.
- `alternates.languages` includes one entry per reviewed locale, using the
  `contentLang` query parameter, plus `x-default` for the source.
- `og:locale` follows the resolved content language.
- JSON-LD uses the resolved title and description.

### Structured content, later phases

The same JSON shape extends to the rest of the organizer content in a second
phase:

- `AgendaItem.titleI18n`, `speakerRoleI18n`
- `EventPerk.titleI18n`, `descriptionI18n`
- `EventUpdate.titleI18n`, `bodyI18n`
- `BoothTenant.descriptionI18n`
- `Venue.transitInfoI18n`

Each keeps the source in the base column and stores overrides per locale with
the same `origin` and `status`. The event page resolves them with the same
language selection.

## Verification

- Opt-in defaults: a null `contentI18n` renders the source and no selector.
- AI drafts require `autoTranslate`; a request without it returns `400`.
- A reviewed locale is never overwritten by a draft.
- Only reviewed locales appear in the selector and in the alternates.
- `contentLang` resolution follows the order above, and an invalid or draft
  locale falls back to the source.
- Metadata, JSON-LD, and `og:locale` follow the resolved language.
- Ownership: a stranger gets `403`; an organizer cannot enable another
  organizer's event; an admin can.
- Rendered check at 390px and 1280px in all six locales, including a long German
  description.

## Risks

- Machine translation can misstate prices, dates, or safety instructions. Review
  status is the control, and drafts never publish.
- Sending organizer content to an external provider needs a clear notice at the
  opt-in switch.
- Content language and interface language can diverge. The selector label and
  the fallback chain must make that obvious.
- The JSON column is not queryable per locale. No current feature needs that;
  if one appears, a normalized table replaces it.
